## 2. 生效资格（正式关卡不得直接调用隔离模式）

- 当前 `g1cIntegration='G1C-PRODUCTION'`、`ownerId`、`g1cOwnership`、`targets` 仅作为隔离验收资格；`g1c`状态带 `testOnly:true`，普通 `newGame` 不拥有任何G1-C厉鬼。
- 将来正式来源必须来自现有真实生产 **敌方行动/initiative 生成器**：`sourceId`须对应当前遭遇的真实源头；`action.type`为已证实的 `body` 或 `domain`；`targetRegion` 是真正被命中区域；`damage`与`ruleWeight/domainWeight`来自规则/能力配置，而非G1-C代码制造的值。
- 鬼火要求目标真实属于可受灵异焚烧的 `spirit` 媒介。对抗只改变可匹配**本次真实动作**的阻断/部分损伤，不伤害不存在的厉鬼HP，不代表毁灭本体或掉落。
- 鬼风仅对明确存在的 `domain` 动作进行领域干扰；`domainWeight>0` 本身不足以证明敌方施放了鬼域。来源、区域或动作类型未知时必须失败关闭，绝不授予“已侵域”证据。
- 鬼压人必须从同一实际作用范围内的身体判定**唯一最高者**，包括玩家和友方；未知身高、并列最高、缺失身体实体认证时不能猜。若目标移动离开、比较关系改变，旧锁定失效。压制只能阻断匹配的真实行动，且允许已有真实灵异抵抗或挣脱；普通力量试探不能免费保证胜利。
- 未来桥接需要记录可追溯的 `encounterId`、`sourceInstanceId`、`actionId`、实际参与者位置与身份可信度，避免两个异源参与者数组被合并成同一个源头；这些字段目前**并不存在于经验证的正式关卡生产合同**，所以不添加虚构适配器。

## 4. 零能量多鬼闭环（本轮已实现的是**真实可选行动的可见提示**）

场景A：两鬼已展开，`energy===0`，**没有鬼压人压住玩家**。现有 `combat:retreat` 不需要技能能量，可结束本次遭遇；**不等于安全收束**：`advanceG1C` 在战斗结束时将尚处于 `CONTROLLED` 的作用标记为 `UNCONTROLLED`，记录 `lost-control`；持久负荷、已支付代价和累计复苏不得恢复。隔离回放应该记录「撤离，留下失控源」，不能把本次记作「全技能平息后完成」。

场景B：玩家是作用范围内被鬼压人的最高者，`energy===0`。原有 `combat:retreat` 被实际身体压制资格禁止，`lift`因能量不足不可用；引擎允许 `combat:force` 等现有合法试探，但可合法失败并推进真实危险，不获得免费挣脱。**是否存在有限回合内的最终脱困/死亡/灵异失控结果，仍须专门仿真审计；不得宣称可活20场。**

以上仅把引擎本来存在的事实展示给玩家，**没有新增资源、没有降费、没有自动强制撤离**。继续区分自然复苏造成的第12/14场停止与未有闭环动作的第0场停止。
