## 原著章节线索（用于核查能力特征，不授权游戏数值）

- 《神秘复苏》“真正无解的重启”（[第四百八十一章文本线索](https://www.hetushu.com/book/7491/5210368.html)）描写李军的青绿色鬼火鬼域与过度使用造成身体焚毁、复苏载体风险。可以支持“鬼火使用会伤害宿主”的方向；**不能**证明复苏达70后每行动扣2生命的游戏候选量化规则。
- “方世明再现”（[第五百九十七章文本线索](https://www.xbiquge345.com/chapter/9643/95029971.html)）明确揭示鬼压人袭击一定范围内身高最高者，且方世明**坐下**影响实际身高比较。将来正式来源不能只存角色固有`heightCm`而忽略触发时姿态、实体位置及相对比较；不能凭身高条目猜出当前被压者，也不能据此认为压制永远不会受反抗。
- 鬼风的具体领域侵入/遮挡对抗仍需要独立核对原著章节。上述章节不能替代鬼风能力的权威证明。

这两处文本是原著情节出处核对线索，与Notion通用玩法优先级不同。已实施G1-C隔离目标身高测试只验证当前测试合同，不自动声明实现了正式世界里的“坐下/站立”变化。

## 新增不可伪造的工程证据入口

- `src/g1c-formal-source.js` 的 `inspectG1CFormalSource(state)` 只读取已有**正式** `events`、当前战斗 `sourceId`、现存 `knocker`声明和鬼眼模拟标记；**不会从用户存档中新的`action`或`heightCm`字段推断正式资格**。
- `FORMAL_AUDIO_PROPAGATION`只标明七中当前已证明的音频威胁，不开放G1-C任意一种技能。
- 其余普通事件被标记 `UNTYPED_EVENT`；敌方ID错位标记 `INVALID_SOURCE`；测试`eyeV6.scenario.simulation` 标记 `SIMULATED_INTENT`；三类结果一律不开放G1-C正式资格。
- `formalG1CReady(state,k)` 目前只对真正有足够来源的鬼返回true；按目前库中的正式声明，**三鬼均为false**。这是故意设置的安全拒绝，不是将场景配置为失败的设计Bug。
- `tests/g1c-formal-source.test.mjs`必须验证：普通新档不赠鬼；全量现有事件不被伪提升；七中音频声明不能冒充鬼域；伪造`domainWeight`、`heightCm`与鬼眼模拟内容不能算正式来源。

## 将来实际接入正式生产场景的步骤（不能跳过）

1. **作者授权**：为本批每只鬼确认完整GDD，标明原著可证实特征/明确的游戏化候选参数/尚未知细节，批准范围、宿主损伤与成长证据规则；同时决定正式玩家独立实例的非夺取式获取路线。
2. **场景数据**：在真实敌方状态机中定义有稳定 `encounterId`／`sourceInstanceId`／`actionId` 的生产意图；`domain`类型必须显式且由已审定的源头规则产生，不得由G1-C代码自己生成；身体/身高数据须有来源、作用区域和并列处理规则。
3. **范围验证**：对每次已授权的敌方动作先验证源头、动作、区域、目标关系，再调用G1-C规则；校验不通过时零资格，不能降级成`shadow`夹具。
4. **真实验收**：在同一生产战斗/独立复苏/结算/存档管线上，通过单鬼及组合5/10/20场、旧档保护、原G1-A/B与鬼眼回归、Chrome真实场景。压力回放有合法危机/失败不代表可以自动算通过。
5. **发布审批**：仅正式资格/获取规则与代码回归均确认后，才可把草稿PR交人工决定是否合并；本文件没有发布授权。

**候选参数提示：** 当前技能能量、独立复苏、持续+1pp、鬼火70/2、鬼压人负担1、集中/侵域额外权重等仍只是隔离工程值，不能据Notion的通用流程自动冻结为正式参数；详细候选费用见 `rules-boundary-candidate.md`。
